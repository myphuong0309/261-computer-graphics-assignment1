\section{Introduction}

This report describes Assignment~1 of the Computer Graphics course (CO3059): \emph{2D and 3D object rendering}. Two interactive graphical applications are implemented with modern, shader-based OpenGL:
\begin{itemize}
  \item \textbf{Part~1 -- Drawing Basic Shapes:} render a variety of 2D and 3D shapes (including a user-defined surface and imported models)
        with a GUI, camera control, geometric transformations and several rendering modes.
  \item \textbf{Part~2 -- Visualization of Atoms and Molecules:} visualize atoms with Bohr's model and simple molecules with the ball-and-stick model.
\end{itemize}
Both applications are written in C++17 on top of OpenGL~3.3 (core profile), GLFW, GLEW, GLM and Dear~ImGui~\cite{opengl33,glfw,glew,glm,imgui}, run on Linux, and share a small common code base.

\paragraph{Organisation of this report.} Section~\ref{sec:overall} describes what is common to both parts (technology, repository, build instructions,
shared classes, lighting model). Sections~\ref{sec:part1} and~\ref{sec:part2} describe Part~1 and Part~2. Section~\ref{sec:conclusion} concludes and gives the link to the source code.

\subsection{Setup, build and run}\label{sec:build}

\begin{verbatim}
sudo apt install build-essential libglfw3-dev libglew-dev    # Ubuntu / Debian

cd cg
make               # build both parts (or: make part1 / make part2)
make run1          # start Part 1 (make run2: Part 2)
make test          # Part 2 unit tests (no GPU needed)
make clean         # remove the build output of both parts
\end{verbatim}
Dear ImGui, GLM and the stb headers are bundled in the repository, so no other dependency has to be installed. The programs must be started from their own folder
(\code{part1\_shapes} or \code{part2\_molecules}) so that \code{shaders/} (and, for Part~1, \code{assets/}) are found; \code{make run1} / \code{make run2} do this.
All data files Part~1 needs to run (sample textures and models) are delivered in \code{part1\_shapes/assets/}.

\subsection{Shared components}

\subsubsection{Shader class}
\code{Shader} (\code{common/src/Shader.cpp}) loads a vertex and a fragment shader from text files, compiles each stage and links the program; compile or link errors are
turned into an exception carrying the GLSL info log. \code{use()} activates the program and the typed setters \code{setMat4}, \code{setMat3}, \code{setVec3}, \code{setFloat}, \code{setInt}, \code{setBool}
upload uniforms by name. Both parts keep their GLSL files in their own \code{shaders/} folder.

\subsubsection{Camera}\label{sec:camera}
The \code{Camera} class (\code{common/src/Camera.cpp}) is an orbit camera defined by \code{yaw}, \code{pitch}, \code{distance} and a \code{target}:
\[
  \text{eye}=\text{target}+d\,\bigl(\cos\varphi\cos\psi,\ \sin\varphi,\ \cos\varphi\sin\psi\bigr),
\]
with $\psi$=yaw and $\varphi$=pitch (clamped to $\pm89^\circ$). The view matrix is \code{lookAt(eye, target, up)} and the projection is a perspective matrix
(default field of view $45^\circ$, near $0.1$, far $100$, adjustable). The class also implements the mouse interaction used by both applications:
dragging the left button changes yaw / pitch (orbit), dragging the right button moves the target in the camera's right / up plane (pan, scaled by the distance),
and the wheel changes the distance (zoom, clamped to $[1,50]$). The applications ignore the mouse while it is over the ImGui panels.

\subsubsection{Phong lighting model}\label{sec:phong}
Both applications light their objects with the Phong reflection model~\cite{phong} and a single point light whose position and ambient / diffuse / specular colors are
editable in the GUI. For a surface point $P$ with unit normal $N$, light direction $L=\mathrm{normalize}(\text{lightPos}-P)$, view direction
$V=\mathrm{normalize}(\text{viewPos}-P)$ and reflection $R=\mathrm{reflect}(-L,N)$, the color is
\[
  C \;=\; L_a\odot m_a \;+\; L_d\odot m_d\,\max(N\!\cdot\!L,\,0) \;+\; L_s\odot m_s\,\max(R\!\cdot\!V,\,0)^{\,n},
\]
where $L_a,L_d,L_s$ are the light's ambient, diffuse and specular colors, $m_a,m_d,m_s$ the material's, $\odot$ is the component-wise product and $n$ is the shininess.
The ambient term keeps the unlit side visible, the diffuse term gives the object its volume, and the specular term adds the bright highlight whose size is controlled by $n$.
The way each part evaluates this formula (per vertex, per fragment) is described in its own section.

\subsection{Geometry: Vertices and Indices of Every Shape}\label{sec:geometry}

\subsubsection{Conventions}

\paragraph{Vertex format.} Every mesh uses the same interleaved vertex (11 floats = 44 bytes):
\begin{center}
\small
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{Attribute} & \textbf{Type} & \textbf{Used for}\\
\midrule
\code{position} (location 0) & \code{vec3} & object-space position\\
\code{normal}   (location 1) & \code{vec3} & unit normal, lighting\\
\code{color}    (location 2) & \code{vec3} & per-vertex color (Gouraud mode, grid, axes)\\
\code{uv}       (location 3) & \code{vec2} & texture coordinates\\
\bottomrule
\end{tabular}
\end{center}

\paragraph{Index buffers.} Each mesh owns two index lists (both \code{unsigned int}):
\begin{itemize}
  \item \code{indices}: a \emph{triangle list}, 3 indices per triangle, drawn with \code{GL\_TRIANGLES}. Triangles are
        wound counter-clockwise when seen from outside (the direction of the vertex normal).
  \item \code{wireIndices}: a \emph{line list}, 2 indices per edge, drawn with \code{GL\_LINES} in wireframe mode
        (Section~\ref{sec:wire}).
\end{itemize}

\paragraph{Notation.} $V$ = number of vertices, $I$ = number of triangle indices, $T=I/3$ = number of triangles,
$E$ = number of wireframe edges. All shapes are centred at the origin and are about one unit large; 2D shapes lie in the
$XY$ plane with normal $+Z$, 3D solids use $Y$ as the up axis.

\paragraph{Why vertices are duplicated.}
A vertex is the unit stored in the vertex buffer: one position \emph{together with} one normal, one color and one UV.
Whenever two faces meet along a sharp edge (cube, tetrahedron, prism sides, cylinder caps) each face needs its own
normal, so the corner is stored once per face --- e.g.\ a cube has $6\times 4=24$ vertices, not 8. Likewise the first and
last column of a sphere or torus have the same position but different $u$ texture coordinates ($0$ and $1$), so the seam
is stored twice. Using indices lets the triangles of a face share the vertices of that face.

\paragraph{Parameters.} The ``default'' columns below use the defaults of the GUI: 48 segments for round shapes,
24 stacks (sphere) / tube segments (torus), 6 prism sides, 5 star points, surface resolution 64.

\subsubsection{2D shapes: triangle fans}

All 2D shapes except the arrow are \emph{convex or star-shaped around the origin}, so they are triangulated as a
\textbf{triangle fan} around a centre vertex $c=(0,0,0)$:
given a counter-clockwise ring of $n$ boundary points $p_0,\dots,p_{n-1}$,
\begin{align*}
  \text{vertices:}\quad & v_0 = c,\quad v_{1+i}=p_i \quad (i=0,\dots,n-1) \qquad\Rightarrow\qquad V=n+1,\\
  \text{triangles:}\quad & \bigl(\,0,\; 1+i,\; 1+((i+1)\bmod n)\,\bigr),\quad i=0,\dots,n-1 \qquad\Rightarrow\qquad I=3n.
\end{align*}
Every vertex has normal $(0,0,1)$. Texture coordinates use planar mapping of the bounding box:
$u=\frac{x-x_{\min}}{x_{\max}-x_{\min}}$, $v=\frac{y-y_{\min}}{y_{\max}-y_{\min}}$. Only the ring changes between shapes:

\subsubsection{Cube}

The cube of side $s=1$ ($h=s/2$) is built face by face. Each face has an outward normal $n$ and two tangent axes $u,v$ with
$u\times v=n$ (so the winding is counter-clockwise from outside). Its four vertices are
\[
  h\,(n-u-v),\quad h\,(n+u-v),\quad h\,(n+u+v),\quad h\,(n-u+v),
  \qquad \text{UV } (0,0),(1,0),(1,1),(0,1),
\]
all with normal $n$, and the two triangles are $(b{+}0,b{+}1,b{+}2)$ and $(b{+}0,b{+}2,b{+}3)$ where $b=4f$ is the
index of the face's first vertex. The six faces:

\midrule

$+Y$ & $(0,1,0)$  & $(1,0,0)$  & $(0,0,-1)$\\

\subsubsection{Sphere}

A UV sphere of radius $r=0.5$ with $S$ sectors (longitude) and $K$ stacks (latitude). Vertex $(i,j)$,
$i=0..K$, $j=0..S$, is stored at index $i(S+1)+j$:
\begin{align*}
  \varphi_i &= \tfrac{\pi}{2}-\tfrac{\pi i}{K}, \qquad \theta_j=\tfrac{2\pi j}{S},\\
  n_{ij} &= (\cos\varphi_i\cos\theta_j,\ \sin\varphi_i,\ \cos\varphi_i\sin\theta_j), \qquad p_{ij}=r\,n_{ij},\\
  (u,v)_{ij} &= \bigl(\tfrac{j}{S},\ 1-\tfrac{i}{K}\bigr).
\end{align*}
For the normals of a sphere centred at the origin the normal equals the normalised position, so no extra computation is needed.
There are $K+1$ rows and $S+1$ columns ($j=S$ duplicates $j=0$ for the texture seam), hence
$V=(S+1)(K+1)$.

Each quad between rows $i,i{+}1$ and columns $j,j{+}1$ is split in two triangles. With $k_1=i(S+1)+j$ and $k_2=k_1+S+1$:
\begin{lstlisting}
if (i != 0)          { push(k1,     k1 + 1, k2);     }   // skipped at the north pole (degenerate)
if (i != stacks - 1) { push(k1 + 1, k2 + 1, k2);     }   // skipped at the south pole
\end{lstlisting}
Counting: $K$ rows of $S$ quads give $2SK$ triangles, minus the $S$ degenerate triangles at each pole:
$T=2SK-2S$, so $I=3T=6S(K-1)$. (Default $S=48,K=24$: $V=1225$, $I=6624$.)

\subsubsection{Cylinder, cone and truncated cone}

All three are the same generator \code{frustum($r_b$, $r_t$, $h$, $N$)} with bottom radius $r_b$, top radius $r_t$,
height $h$ ($=1$) and $N$ segments (cylinder $r_t=r_b=0.5$, cone $r_t=0$, truncated cone $r_t=0.25$ by default).

\paragraph{Side.} For $i=0..N$ with $a_i=2\pi i/N$ two vertices are created (bottom at index $2i$, top at $2i{+}1$):
\begin{align*}
  \text{bottom}&=(r_b\cos a_i,\ -\tfrac h2,\ r_b\sin a_i), \quad \text{top}=(r_t\cos a_i,\ \tfrac h2,\ r_t\sin a_i),\\
  n_i &= \mathrm{normalize}\bigl(h\cos a_i,\ r_b-r_t,\ h\sin a_i\bigr), \qquad (u,v)=(i/N,\,0)\ \text{and}\ (i/N,\,1).
\end{align*}
The slanted normal (the $y$-component $r_b-r_t$) is what makes the cone and truncated cone shade correctly; for the cylinder
it reduces to $(\cos a_i,0,\sin a_i)$. For segment $i<N$ with $b_0=2i$, $t_0=2i+1$, $b_1=2i+2$, $t_1=2i+3$:
triangles $(b_0,t_0,b_1)$ and $(b_1,t_0,t_1)$. So the side has $2(N+1)$ vertices and $2N$ triangles
(for the cone, $N$ of them are degenerate because $t_0=t_1$ is the apex; they are harmless and are ignored in wireframe).

\paragraph{Caps.} A cap is added only if its radius is positive. A cap has its own vertices (its normal is $\pm Y$, not
the side normal): one centre plus $N+1$ ring vertices $(r\cos a_i, \pm\tfrac h2, r\sin a_i)$ with $uv=(\tfrac12+\tfrac12\cos a_i,\ \tfrac12+\tfrac12\sin a_i)$,
and $N$ triangles $(c,\,p_i,\,p_{i+1})$ for the bottom cap and $(c,\,p_{i+1},\,p_i)$ for the top cap.

\subsubsection{Tetrahedron}

A regular tetrahedron of edge $e=1.2$ is inscribed in a cube: with $k=e/(2\sqrt2)\approx0.4243$ its corners are
\[
  P_0=k(1,1,1),\ P_1=k(1,-1,-1),\ P_2=k(-1,1,-1),\ P_3=k(-1,-1,1),
\]
(every pair is $2\sqrt2\,k=e$ apart). Each of the 4 faces $(P_0P_1P_2)$, $(P_0P_3P_1)$, $(P_0P_2P_3)$, $(P_1P_3P_2)$ gets its own
three vertices carrying the face normal $n=\mathrm{normalize}\bigl((b-a)\times(c-a)\bigr)$; if $n\cdot(a+b+c)<0$ the normal points
inward, so $b$ and $c$ are swapped and $n$ is negated. UV are $(0,0),(1,0),(\tfrac12,1)$. Indices: face $f$ uses
$(3f,3f{+}1,3f{+}2)$. $V=4\cdot3=12$, $I=12$.

\subsubsection{Torus}

A torus with ring radius $R=0.5$ and tube radius $r$ (default $0.18$), $M$ segments around the ring and $m$ around the tube.
Vertex $(i,j)$, $i=0..M$, $j=0..m$ at index $i(m+1)+j$, with $\theta_i=2\pi i/M$, $\phi_j=2\pi j/m$:
\begin{align*}
  p_{ij} &= \bigl((R+r\cos\phi_j)\cos\theta_i,\ \ r\sin\phi_j,\ \ (R+r\cos\phi_j)\sin\theta_i\bigr),\\
  n_{ij} &= (\cos\phi_j\cos\theta_i,\ \sin\phi_j,\ \cos\phi_j\sin\theta_i), \qquad (u,v)=(i/M,\ j/m).
\end{align*}
The normal is the direction from the tube's centre circle to the surface point. With $a=i(m+1)+j$ and $b=a+m+1$ the quad is split into
$(a,\,a{+}1,\,b)$ and $(b,\,a{+}1,\,b{+}1)$. $V=(M+1)(m+1)$, $T=2Mm$, $I=6Mm$.

\subsubsection{Prism}

A regular $n$-gon prism (radius $0.5$, height $1$, axis $Y$). Each side face $i$ lies between angles $a_0=2\pi i/n$ and $a_1=2\pi(i+1)/n$
and has its own four vertices (flat normal $=(\cos\frac{a_0+a_1}{2},0,\sin\frac{a_0+a_1}{2})$), in the order
bottom-$a_0$, top-$a_0$, bottom-$a_1$, top-$a_1$ with triangles $(0,1,2)$ and $(2,1,3)$ (offset by $4i$).
The two caps are the same disc caps as for the cylinder, built with $N=n$. Therefore
$V=4n+2(n+2)=6n+4$ and $T=2n+n+n=4n$, $I=12n$.

\subsubsection{Wireframe edges}\label{sec:wire}

In wireframe mode the object is shown as its \emph{triangle mesh}: every edge of every triangle is drawn as a line, so the
triangulation built in the previous subsections becomes visible (the diagonal that splits each face of the cube, the radial lines of a
fan or a cap, the quad diagonals of a sphere or torus). Each mesh keeps a separate line list \code{wireIndices}, built once by
\code{buildWireIndices()}:
\begin{enumerate}
  \item Vertices with the same position (quantised to $10^{-4}$) get the same \emph{canonical id}, so the duplicated vertices of a cube
        corner or of a texture seam are recognised as one point and their shared edge is drawn once, not twice.
  \item Every non-degenerate triangle contributes its 3 edges; an edge is stored (as a pair of vertex indices for \code{GL\_LINES})
        the first time its pair of canonical ids is met. Degenerate triangles (sphere poles, cone apex) are skipped.
\end{enumerate}
Since a triangle mesh is drawn, $E$ follows from the triangulation; the counts are the $E$ column of Table~\ref{tab:counts}:
\begin{itemize}
  \item \textbf{2D fans:} $n$ boundary sides plus $n$ radial lines to the centre, $E=2n$ (star $4p$, rectangle and trapezoid 8);
        the arrow has its 7 outline edges plus 4 interior diagonals, $E=11$.
  \item \textbf{Cube:} 12 edges plus one diagonal per face, $E=18$; \textbf{tetrahedron:} $E=6$.
  \item \textbf{Cylinder / truncated cone:} $N$ vertical lines, $N$ side diagonals, 2 rims of $N$ segments and $2N$ cap radials, $E=6N$;
        \textbf{cone:} $N$ slant lines, $N$ rim segments and $N$ base radials, $E=3N$; \textbf{prism:} likewise $E=6n$.
  \item \textbf{Sphere:} $SK$ meridian segments, $S(K-1)$ latitude segments and $S(K-2)$ quad diagonals, $E=3S(K-1)$;
        \textbf{torus:} $3Mm$ (two grid directions and one diagonal per quad).
  \item \textbf{Surface:} $2N(N+1)$ grid lines plus $N^2$ diagonals, $E=3N^2+2N$ when every cell is finite.
\end{itemize}

\subsubsection{Normals, colors and texture coordinates}

\begin{itemize}
  \item \textbf{Normals:} analytic for sphere, torus, cylinder / cone, flat per face for cube / tetrahedron / prism, analytic gradient for surfaces,
        area-weighted vertex averages for imported models that have no normals.
  \item \textbf{Vertex colors} (used by Gouraud mode): by default a rainbow computed from the normalised position inside the bounding box,
        $t=\text{mean}\bigl(\tfrac{x-x_{\min}}{\Delta x},\tfrac{y-y_{\min}}{\Delta y},\tfrac{z-z_{\min}}{\Delta z}\bigr)$ over the non-flat axes and
        hue $=0.83\,t$; optionally a two-color gradient $\mathrm{mix}(A,B,t)$ chosen in the GUI. For surfaces $t$ is the height.
  \item \textbf{UV:} sphere and torus by their parameters ($j/S$ etc.), cylinder / prism by angle and height, caps by a circle mapped to $[0,1]^2$,
        cube and tetrahedron per face, 2D shapes by their bounding box.
\end{itemize}

\subsection{Surface $z=f(x,y)$ and Imported Models}

\subsubsection{Mathematical surface}\label{sec:surface}

The user types a formula such as \code{sin(x)*cos(y)} and a range $[x_{\min},x_{\max}]\times[y_{\min},y_{\max}]$ with a grid of
$N\times N$ cells (default $N=64$, up to 400).

\paragraph{Formula parser.} \code{ExprParser.cpp} is a recursive-descent parser that compiles the text into a small expression tree
evaluated for every grid point. Grammar (highest precedence last):
{\small
\begin{align*}
  \textit{expr} &::= \textit{term}\ ((\texttt{+}|\texttt{-})\ \textit{term})^* &
  \textit{unary} &::= (\texttt{-}|\texttt{+})\ \textit{unary}\ |\ \textit{power}\\
  \textit{term} &::= \textit{unary}\ ((\texttt{*}|\texttt{/})\ \textit{unary})^* &
  \textit{power} &::= \textit{primary}\ (\texttt{\textasciicircum}\ \textit{unary})?\\
  \textit{primary} &::= \text{number}\ |\ x\ |\ y\ |\ \pi\ |\ e\ |\ \textit{name}\,(\textit{expr}\,[,\textit{expr}])\ |\ (\textit{expr}) &&
\end{align*}}
Power is right-associative and binds tighter than unary minus ($-x^2=-(x^2)$, $2^{3^2}=512$). Implicit multiplication
(\code{2x}, \code{3sin(x)}) and a leading \code{z=} are accepted. Functions: \code{sin cos tan asin acos atan sinh cosh tanh sqrt abs exp log ln floor ceil}
and the two-argument \code{pow atan2 min max}. Errors (unknown name, missing parenthesis, wrong argument count) are reported in the
GUI together with the position and the previous mesh is kept.

\paragraph{Vertices.} For $i,j=0..N$: $x_i=x_{\min}+i\,\Delta x$, $y_j=y_{\min}+j\,\Delta y$, $z_{ij}=f(x_i,y_j)$. The surface is centred in $x,y$ and uniformly scaled
by $s=1/\max(\Delta X,\Delta Y)$ so that its footprint is about one unit wide (it can be scaled like any other object). The mathematical $z$-axis
becomes world ``up'' ($+Y$) and the mathematical $y$ becomes $-Z$ so that the coordinate system stays right-handed:
\[
  p_{ij}=\bigl(s\,(x_i-c_x),\ s\,z_{ij},\ -s\,(y_j-c_y)\bigr),\qquad
  n_{ij}=\mathrm{normalize}(-f_x,\ 1,\ f_y),
\]
where $f_x,f_y$ are central differences of $f$ ($h=10^{-4}$ of the range), and $(u,v)=(i/N,\,j/N)$. $V=(N+1)^2$, stored at index $a=j(N+1)+i$.

\paragraph{Indices.} For every cell with corners $a=(i,j)$, $b=(i{+}1,j)$, $c=(i,j{+}1)$, $d=(i{+}1,j{+}1)$ the triangles are
$(a,b,c)$ and $(b,d,c)$ (counter-clockwise seen from $+Y$). A cell is skipped when any corner has $f$ non-finite or $|f|>10^3$
(e.g.\ $\log x$ for $x\le0$, $1/x$ at $0$), so $I=6N^2$ for a fully finite function and less otherwise. If no cell is finite the surface
is rejected with an error message.

\subsubsection{Importing \texttt{.obj} and \texttt{.ply} models}\label{sec:models}

Both loaders are written by hand (no external model library) and fill the same \code{MeshData}.

\paragraph{OBJ.} Lines \code{v}, \code{vt}, \code{vn} fill three arrays; each \code{f} corner \code{v/vt/vn} (any of \code{v}, \code{v/vt}, \code{v//vn}, \code{v/vt/vn};
negative indices allowed) is mapped to a GPU vertex. A vertex is the \emph{unique triple} (position, uv, normal) --- a lookup table
reuses an existing vertex when the same triple appears again --- so a vertex shared by many faces is stored once, but a vertex with two
different normals or UVs is split. A face with $k_f$ corners becomes a triangle fan $(f_0,f_i,f_{i+1})$, $i=1..k_f-2$, thus
$I=3\sum_f(k_f-2)$. (Fan triangulation is exact for the convex faces found in typical models.)

\paragraph{PLY.} The header is parsed generically (\code{ascii}, \code{binary\_little\_endian}, \code{binary\_big\_endian}; all scalar types; list properties).
For the \code{vertex} element the properties \code{x y z}, \code{nx ny nz}, \code{s t}/\code{u v}, \code{red green blue} are used, and for \code{face} the
list \code{vertex\_indices} is fan-triangulated as above. Unknown elements and properties are skipped.

\paragraph{Post-processing.} The model is re-centred on its bounding-box centre and scaled so that its largest extent is 1;
normals are generated (area-weighted, merged by position) if the file has none; spherical UV are generated if it has none; vertex colors are
kept when present (PLY) and rainbow otherwise; finally the wire edge list is built. Samples (\code{assets/models/}): \code{torusknot.obj}
(3417 vertices, 6400 triangles, with normals and UV), \code{octahedron.obj} (6 vertices, 8 triangles, positions only),
\code{icosphere\_colored.ply} (ascii, 42 vertices, 80 triangles, colors) and \code{cube\_binary.ply} (binary, 8 vertices, quads $\to$ 12 triangles).

\subsection{Rendering Modes and Shaders}\label{sec:render}

All objects are drawn by \emph{one} shader program (\code{shapes.vert}, \code{shapes.frag}). The integer uniform \code{mode}
chosen per object selects the mode:

\begin{center}
\small
\begin{tabularx}{\textwidth}{@{}cl X@{}}
\toprule
\code{mode} & \textbf{Render mode} & \textbf{Color computation}\\
\midrule
0 & Flat color & \code{objectColor}, no lighting (a single uniform color).\\
1 & Gouraud & Lighting evaluated per \emph{vertex} in the vertex shader from the vertex color; the resulting color is interpolated across the triangle.\\
2 & Phong & Normal interpolated; lighting evaluated per \emph{fragment} with \code{objectColor}.\\
3 & Texture & Same lighting as Phong, but the albedo is \code{texture(tex, uv*uvScale)}.\\
4 & Wireframe & \code{objectColor}, drawn with \code{GL\_LINES} from \code{wireIndices}.\\
5 & (internal) & Unlit vertex color: ground grid and axes.\\
\bottomrule
\end{tabularx}
\end{center}

\paragraph{Lighting model.} Modes 1--3 use the Phong reflection model of Section~\ref{sec:phong} with one point light. In Part~1 the material is
reduced to three numbers per object: the \emph{albedo} $c$ (the object color, the vertex color or the texel), which serves as both $m_a$ and $m_d$, the
\emph{Specular} slider ($m_s$ is a gray value) and the \emph{Shininess} ($n$). The lighting is \emph{two-sided}: if $N\cdot V<0$ the normal is flipped,
so the back of a 2D shape and meshes with inconsistent winding are lit correctly (face culling is disabled).

\begin{lstlisting}[language=GLSL,caption={Core of the lighting function (both shaders).}]
vec3 phong(vec3 N, vec3 P, vec3 albedo) {
    vec3 V = normalize(viewPos - P);
    if (dot(N, V) < 0.0) N = -N;                       // two-sided lighting
    vec3 L = normalize(light.position - P);
    vec3  ambient  = light.ambient * albedo;
    float diff     = max(dot(N, L), 0.0);
    vec3  diffuse  = light.diffuse * diff * albedo;
    vec3  R        = reflect(-L, N);
    float spec     = diff > 0.0 ? pow(max(dot(V, R), 0.0), shininess) : 0.0;
    return ambient + diffuse + light.specular * spec * specularStrength;
}
\end{lstlisting}

\paragraph{Gouraud vs.\ Phong.} In Gouraud mode~\cite{gouraud} \code{phong()} is called in the \emph{vertex} shader with the vertex color as albedo and
the result is passed as an interpolated \code{out} variable; the fragment shader only outputs it. In Phong mode the vertex shader passes the
world position and normal, and the fragment shader calls \code{phong()} for every pixel. The difference is visible in the highlight on low-resolution
meshes: Gouraud can miss or smear a highlight that falls inside a triangle.

\paragraph{Highlights on flat faces.} A curved surface always has some point whose normal reflects the light straight to the eye, so a sphere or torus
shows a bright spot. A flat face has a single normal, hence a single reflection direction: the highlight is either one broad bright area (if the
mirror point of the light falls on the face) or absent (if it falls outside the face, as with the default light on the cube in
Figure~\ref{fig:light}a). With the light placed so that the mirror point lies on the top face (Figure~\ref{fig:light}b) the cube shows its highlight.
This is the expected behaviour of the Phong model and not a rendering error; lowering the shininess widens the highlight.

\subsection{Object Transformations}\label{sec:transform}

Each object has a translation $t$, Euler rotation angles $(\theta_x,\theta_y,\theta_z)$ in degrees and a (non-uniform) scale $s$.
The model matrix is
\[
  M = T(t)\; R_z(\theta_z)\, R_y(\theta_y)\, R_x(\theta_x)\; S(s),
\]
i.e.\ a vertex is first scaled, then rotated about $X$, $Y$, $Z$ and finally translated. $M$ is uploaded as the \code{model} uniform, and
normals are transformed with the normal matrix $\bigl(M^{-1}\bigr)^{T}$ (upper $3\times3$), which stays correct under non-uniform scaling.
The inspector exposes these as sliders and shows the current $4\times4$ matrix. \emph{Ctrl\,+\,left drag} in the viewport rotates the selected object, and
\emph{Reset transform} returns it to the centre.

\subsubsection{Scene graph design}

The central design pattern is a \textbf{hierarchical scene graph}. Each \code{SceneNode} stores a local transform made of a position,
a rotation (axis and angle) and a scale, an optional pointer to a shared mesh, a material and its children. Drawing is recursive: a node
computes $M_{\text{world}}=M_{\text{parent}}\,M_{\text{local}}$, uploads the model and normal matrices and its material, issues the draw call
and recurses into its children with $M_{\text{world}}$ (Section~\ref{sec:hier}). Moving a node therefore moves its whole subtree; this is what
attaches an electron to its rotating orbit pivot and the atoms and bonds of a molecule to the rotating root. Animations are expressed as
\code{update(dt)} overrides of three node types (\code{OrbitNode}, \code{VibrationNode}, \code{MolRotNode}) and are applied by one recursive
\code{updateTree()} before drawing. Figure~\ref{fig:sg2} shows both trees.

\subsection{Mathematical Foundations}\label{sec:math2}

This section collects the transformations used by Part~2. Points $\mathbf p\in\mathbb R^3$ are written in homogeneous coordinates
$(\mathbf p,1)$ and directions as $(\mathbf v,0)$, so that a translation acts on points but not on directions.

\subsubsection{Local transform and axis--angle rotations}

A node's local matrix is:
\begin{gather*}
  M_{\text{local}} = T(\mathbf t)\,R(\hat{\mathbf a},\theta)\,S(\mathbf s),\\
  T(\mathbf t)=\begin{pmatrix} I_3 & \mathbf t\\ \mathbf 0^{T} & 1\end{pmatrix},\qquad
  R=\begin{pmatrix} R_3 & \mathbf 0\\ \mathbf 0^{T} & 1\end{pmatrix},\qquad
  S=\operatorname{diag}(s_x,s_y,s_z,1),
\end{gather*}
so that $M_{\text{local}}\mathbf p=\mathbf t+R_3\,(\mathbf s\odot\mathbf p)$: a vertex is scaled, then rotated, then translated.
The rotation by angle $\theta$ about the unit axis $\hat{\mathbf a}$  is given by Rodrigues' formula:
\begin{equation}
  R_3(\hat{\mathbf a},\theta)=I+\sin\theta\,K+(1-\cos\theta)\,K^2,\qquad
  K=[\hat{\mathbf a}]_\times=\begin{pmatrix}0&-a_z&a_y\\a_z&0&-a_x\\-a_y&a_x&0\end{pmatrix},
  \label{eq:rodrigues}
\end{equation}
or, applied to a vector, $R_3\mathbf v=\mathbf v\cos\theta+(\hat{\mathbf a}\times\mathbf v)\sin\theta+\hat{\mathbf a}\,(\hat{\mathbf a}\cdot\mathbf v)(1-\cos\theta)$.
The rotations about the coordinate axes used below are the special cases
\begin{gather*}
  R_x(\tau)=\begin{pmatrix}1&0&0\\0&\cos\tau&-\sin\tau\\0&\sin\tau&\cos\tau\end{pmatrix},\qquad
  R_y(\psi)=\begin{pmatrix}\cos\psi&0&\sin\psi\\0&1&0\\-\sin\psi&0&\cos\psi\end{pmatrix},\\
  R_z(\theta)=\begin{pmatrix}\cos\theta&-\sin\theta&0\\\sin\theta&\cos\theta&0\\0&0&1\end{pmatrix}.
\end{gather*}
Whith 2 facts are used: rotations are isometries ($\|R\mathbf v\|=\|\mathbf v\|$), and $R^{-1}=R^{T}$.

\subsubsection{Composition along the hierarchy}\label{sec:hier}

For a node $v$ whose path from the root is $v_0,v_1,\dots,v_k=v$,
\[
  M_{\text{world}}(v)=M_{\text{local}}(v_0)\,M_{\text{local}}(v_1)\cdots M_{\text{local}}(v_k),
\]
computed recursively as 
\[M_{\text{world}}(v)=M_{\text{world}}(\text{parent}(v))\,M_{\text{local}}(v)\] 
with $M_{\text{world}}(\text{root's parent})=I$.
Each node costs one $4\times4$ product (and one inversion for the normal matrix). Because matrix products are associative, changing $M_{\text{local}}$ of one node changes the world matrix of exactly its subtree,
by the same left factor: the subtree moves rigidly with its root.

\subsubsection{Transforming normals}

\begin{proposition}[normal matrix]\label{prop:normal}
Let $A$ be the upper-left $3\times3$ block of an invertible model matrix $M$. If $\mathbf n$ is normal to a surface at $\mathbf p$,
then $\mathbf n'=A^{-T}\mathbf n$ is normal to the transformed surface at $M\mathbf p$.
\end{proposition}
\noindent\textit{Proof.} A tangent vector is the limit of a difference of two surface points; the translation cancels in the difference,
so tangents transform as $\mathbf t'=A\mathbf t$. Then
$\mathbf n'^{T}\mathbf t'=(A^{-T}\mathbf n)^{T}A\mathbf t=\mathbf n^{T}A^{-1}A\,\mathbf t=\mathbf n^{T}\mathbf t=0$ for every tangent $\mathbf t$. \hfill$\square$. 

The normal matrix is $(M_{\text{world}}^{-1})^{T}$ restricted to $3\times3$; for an affine $M=\bigl(\begin{smallmatrix}A&\mathbf t\\0&1\end{smallmatrix}\bigr)$: this block is exactly $A^{-T}$, since $M^{-1}=\bigl(\begin{smallmatrix}A^{-1}&-A^{-1}\mathbf t\\0&1\end{smallmatrix}\bigr)$. For a rotation $A^{-T}=A$, and for a uniform scale $A^{-T}$ is a multiple of $A$. The bond cylinders are scaled non-uniformly, $A=R_3\operatorname{diag}(2\rho,\ell,2\rho)$; their normals ($\pm\hat{\mathbf y}$ on the caps,
$(\cos\varphi,0,\sin\varphi)$ on the side) happen to be eigenvectors of the scale, so $A\mathbf n$ and $A^{-T}\mathbf n$ point the same way.

\subsubsection{Camera, view and projection}\label{sec:camera2}

\paragraph{Eye position.} The shared orbit camera (Section~\ref{sec:camera}) places the eye at
$\mathbf e=\mathbf c+d\,(\cos\varphi\cos\psi,\ \sin\varphi,\ \cos\varphi\sin\psi)$ around the target $\mathbf c$, with yaw $\psi$, pitch $\varphi$
and distance $d$. Our Part 2 resets it to $\psi=90^\circ$, $\varphi=30^\circ$, for example, \ $\mathbf e=d\,(0,\tfrac12,\tfrac{\sqrt3}{2})$: the camera is on
the $+Z$ side, so the world $X$ axis points to the right, $Y$ up and $Z$ towards the viewer, and the default light $(5,8,5)$ is in front
of the scene, above and to the right.

\paragraph{View matrix.} \code{lookAt} builds the orthonormal camera basis
\[
  \mathbf f=\frac{\mathbf c-\mathbf e}{\|\mathbf c-\mathbf e\|},\qquad
  \mathbf r=\frac{\mathbf f\times\hat{\mathbf y}}{\|\mathbf f\times\hat{\mathbf y}\|},\qquad
  \mathbf u=\mathbf r\times\mathbf f,
  \qquad
  V=\begin{pmatrix}
    \mathbf r^{T} & -\mathbf r\cdot\mathbf e\\
    \mathbf u^{T} & -\mathbf u\cdot\mathbf e\\
    -\mathbf f^{T} & \mathbf f\cdot\mathbf e\\
    \mathbf 0^{T} & 1
  \end{pmatrix},
\]
which maps the eye to the origin and the viewing direction to $-Z$. The basis is undefined when $\mathbf f\parallel\hat{\mathbf y}$
($\mathbf f\times\hat{\mathbf y}=\mathbf 0$); this is why the pitch is clamped to $[-89^\circ,89^\circ]$.

\paragraph{Projection and viewport.} With vertical field of view $\alpha$ ($45^\circ$), aspect ratio $a$, near $n=0.1$ and far $f=100$,
\[
  P=\begin{pmatrix}
    \frac{1}{a\tan(\alpha/2)}&0&0&0\\
    0&\frac{1}{\tan(\alpha/2)}&0&0\\
    0&0&-\frac{f+n}{f-n}&-\frac{2fn}{f-n}\\
    0&0&-1&0
  \end{pmatrix},
\]
\[
  \mathbf p_{\text{clip}}=P\,V\,M_{\text{world}}\,(\mathbf p,1)^{T},\qquad
  \mathbf p_{\text{ndc}}=\mathbf p_{\text{clip}}/w_{\text{clip}},\qquad w_{\text{clip}}=-z_{\text{eye}}.
\]
The depth $z_{\text{ndc}}=\frac{f+n}{f-n}+\frac{2fn}{(f-n)\,z_{\text{eye}}}$ is hyperbolic in $z_{\text{eye}}$, so the depth precision is
concentrated near the near plane.
Our control panel covers the left $330$~px of the window, so the scene is drawn in the viewport $x\in[330,W)$ with
$a=(W-330)/H$; using the aspect of the viewport (not of the window) keeps circles circular.

\paragraph{Automatic framing.}
\begin{proposition}\label{prop:fit}
A sphere of radius $R$ centred on the viewing axis at distance $d$ lies inside the view cone of half-angle $\alpha/2$ if and only if
$d\sin(\alpha/2)\ge R$.
\end{proposition}
\noindent\textit{Proof.} The distance from the centre of the sphere to a generator line of the cone is the leg opposite to the angle $\alpha/2$
in the right triangle whose hypotenuse is the segment of length $d$ from the eye to the centre, i.e.\ $d\sin(\alpha/2)$. The sphere is inside
the cone iff this distance is at least $R$. \hfill$\square$

Since $a\ge1$, the vertical half-angle is the binding one. When a scene is built or the view is reset, the camera distance is set to
$d=1.25\,R/\sin(\alpha/2)$ (25\,\% margin), with $R=r_{\text{outer}}+\rho_e$ for an atom (outermost shell plus electron radius) and
$R=R_{\text{fit}}=2.2$ for a molecule (as in Section~\ref{sec:norm}): $d=4.25$ (H), $7.19$ (C), $10.78$ (Na), $15.03$ (Ca) and $7.19$ for every molecule.


\subsubsection{Phong lighting per fragment}\label{sec:phong2}

Every fragment is lit with the Phong model of Section~\ref{sec:phong}, with the light and material colors of the node:
\begin{equation}
  C=L_a\odot m_a+L_d\odot m_d\,\max(N\!\cdot\!L,0)+[N\!\cdot\!L>0]\;L_s\odot m_s\,\max(R\!\cdot\!V,0)^{\,n},
  \label{eq:phong2}
\end{equation}
with $R=2(N\cdot L)N-L$ (by GLSL \code{reflect(-L, N)}) and $[\,\cdot\,]$ equal to 1 if the condition holds and 0 otherwise.

(1)~The normal interpolated across a triangle is shorter than one: for unit $\mathbf a,\mathbf b$:
\[\|(1-t)\mathbf a+t\mathbf b\|^2=1-2t(1-t)(1-\mathbf a\cdot\mathbf b)<1\]
so the fragment shader renormalises it.

(2)~The indicator $[N\cdot L>0]$: when the light is behind the surface, $R\cdot N=N\cdot L<0$ so $R$ points into the surface, yet
$R\cdot V$ can still be positive at grazing viewing angles, which produced highlights on the dark side, the specular term is now
evaluated only where the diffuse term is non-zero.

\subsection{Visualizing Atoms: Bohr's Model}\label{sec:bohr}

\subsubsection{Physical model and brief physical mechanism}\label{sec:bohrphys}

In Bohr's model (1913)~\cite{bohr,bohrwiki} an electron of mass $m_e$ moves on a circle of radius $r$ around a nucleus of charge $Ze$, the Coulomb
attraction providing the centripetal force, and its angular momentum is quantised:
\[
  \frac{Ze^2}{4\pi\varepsilon_0 r^2}=\frac{m_e v^2}{r},\qquad L=m_e v r=n\hbar,\quad n=1,2,3,\dots
\]
Substituting $v=n\hbar/(m_e r)$ into the force balance gives $Ze^2/(4\pi\varepsilon_0)=n^2\hbar^2/(m_e r)$, hence
\begin{align}
  r_n &= \frac{n^2}{Z}\,a_0, && a_0=\frac{4\pi\varepsilon_0\hbar^2}{m_e e^2}\approx0.529\ \text{\AA},\nonumber\\
  v_n &= \frac{Z}{n}\,\alpha c, && \alpha=\frac{e^2}{4\pi\varepsilon_0\hbar c}\approx\frac{1}{137},\nonumber\\
  E_n &= \tfrac12 m_e v_n^2-\frac{Ze^2}{4\pi\varepsilon_0 r_n}=-\frac{Z^2}{n^2}\,\frac{\alpha^2 m_e c^2}{2}
       && \approx-13.6\ \text{eV}\cdot\frac{Z^2}{n^2},\nonumber\\
  \omega_n &= \frac{v_n}{r_n}=\frac{Z^2}{n^3}\,\frac{\alpha c}{a_0}, && T_n=\frac{2\pi}{\omega_n}=\frac{n^3}{Z^2}\,T_1,\quad T_1\approx1.52\times10^{-16}\ \text{s}.
  \label{eq:bohr}
\end{align}
The orbits are concentric circles whose radius grow like $n^2$, and the outer electrons are slower ($v\propto1/n$) and turn much more slowly
($\omega\propto1/n^3$).

\paragraph{Shells and their occupation.} Shell $n$ (K, L, M, N for $n=1..4$) can hold at most $2n^2$ electrons: in the quantum-mechanical
refinement of the model a shell contains the subshells $l=0,\dots,n-1$, each with $2l+1$ orbitals of two spin states, and
$\sum_{l=0}^{n-1}2(2l+1)=2n^2$ (Pauli principle). The table of \code{AtomData.cpp} stores, for each element, the number of electrons in each shell,
for instance, the electrons of all subshells with the same $n$ (Table~\ref{tab:elements}). Shells do not always fill in order: potassium and calcium
place electrons in $n=4$ while the M shell holds only 8 of its 18 electrons, because the $4s$ subshell lies below $3d$ (Madelung $n+l$ rule). For example:
iron is $[\text{Ar}]\,3d^6 4s^2\to(2,8,14,2)$ and copper $[\text{Ar}]\,3d^{10}4s^1\to(2,8,18,1)$. The tests check
$\sum_k n_k=Z$ and $n_k\le2k^2$ for every element.

\subsubsection{Mitigating from the physical model to the visual model}\label{sec:bohrvis}

Equations \eqref{eq:bohr} cannot be drawn literally. With $r_n\propto n^2$ the N shell is 16 times larger than the K shell: at the zoom
where the N shell fits in the window the K shell would be a few pixels wide. With $\omega_n\propto n^{-3}$ an N electron needs 64 times longer
than a K electron for one revolution . And the real period, $T_1\approx1.5\times10^{-16}$~s,
must in any case be slowed down by about $2.6\times10^{16}$. The visual model keeps the qualitative laws (larger and slower outer shells) but
compresses their range:
\[
  r_k = 0.1\,k^2+0.6\,k+0.5 \quad(k=1,\dots,4):\qquad r_k=1.2,\ 2.1,\ 3.2,\ 4.5 ,
\]
still a quadratic in $k$, like Bohr's, but dominated by its linear term ($r_4/r_1=3.75$ instead of 16), with a spacing
$r_{k+1}-r_k\ge0.9$ much larger than the electron diameter $2\rho_e=0.2$. The angular speeds $\omega_k=90,60,45,35^\circ$/s decrease
with $k$, but the linear speeds $v_k=\omega_k r_k$ are almost equal, so that every electron visibly moves (Table~\ref{tab:shells}).

\subsubsection{Electron kinematics}\label{sec:kin}

Composing the local matrices from the root to electron $e$ ($e=0,\dots,n_k-1$) of shell $k$ gives the centre of the electron sphere:
\begin{gather}
  \mathbf c_{k,e}(t)=R_x(\tau_k)\,R_z(\theta)\,T(r_k,0,0)\,\mathbf 0
  = r_k\begin{pmatrix}\cos\theta\\ \cos\tau_k\sin\theta\\ \sin\tau_k\sin\theta\end{pmatrix},\nonumber\\
  \theta=\theta_{k,e}(t)=\frac{360^\circ e}{n_k}+s\,\omega_k t
  \label{eq:electron}
\end{gather}
(angles taken modulo $360^\circ$), where $s$ is the speed multiplier of the GUI (indeed $R_z(\theta)(r,0,0)^T=r(\cos\theta,\sin\theta,0)^T$ and $R_x(\tau)(x,y,0)^T=(x,\,y\cos\tau,\,y\sin\tau)^T$).
The initial phases $360^\circ e/n_k$ spread the electrons of a shell evenly.

\begin{proposition}[electrons stay on their ring]\label{prop:onring}
For every $t$, $\|\mathbf c_{k,e}(t)\|=r_k$ and $\mathbf c_{k,e}(t)\cdot\mathbf n_k=0$ with $\mathbf n_k=R_x(\tau_k)\hat{\mathbf z}=(0,-\sin\tau_k,\cos\tau_k)$.
Hence every electron of shell $k$ moves on the circle $\{\mathbf x:\|\mathbf x\|=r_k,\ \mathbf x\cdot\mathbf n_k=0\}$, which is the centre circle of ring~$k$.
\end{proposition}
\noindent\textit{Proof.} $R_x$ and $R_z$ are isometries, so $\|\mathbf c\|=\|(r_k,0,0)\|=r_k$. From~\eqref{eq:electron},
$\mathbf c\cdot\mathbf n_k=r_k\sin\theta\,(-\cos\tau_k\sin\tau_k+\sin\tau_k\cos\tau_k)=0$. The ring is the torus generated in the $XY$ plane with
centre circle $\{\|\mathbf x\|=r_k,\ x_3=0\}$, transformed by the same $R_x(\tau_k)$, which maps the plane $x_3=0$ to the plane $\mathbf x\cdot\mathbf n_k=0$. 

\begin{proposition}[no overlaps]\label{prop:nooverlap}
For all elements of Table~\ref{tab:elements} and all $t$: (a)~two electrons of different shells are at least $0.9$ apart;
(b)~two electrons of shell $k$ are at least $2r_k\sin(\pi/n_k)\ge1.11$ apart; (c)~every electron is at distance $r_k\ge1.2$ from the
centre. Since $2\rho_e=0.2$ and $\rho_N+\rho_e=0.55$, electron spheres never intersect each other or the nucleus.
\end{proposition}
\noindent\textit{Proof.} (a)~By the reverse triangle inequality and Proposition~\ref{prop:onring},
$\|\mathbf c-\mathbf c'\|\ge\bigl|\|\mathbf c\|-\|\mathbf c'\|\bigr|=|r_k-r_{k'}|\ge0.9$. \\
(b)~All electrons of a shell share $\omega_k$, so their phase differences stay equal to $360^\circ m/n_k$, $m\ne0$; two points of a circle of radius
$r$ separated by the angle $\Delta$ are at the chord distance $2r\sin(\Delta/2)\ge2r\sin(\pi/n_k)$. The smallest value over the 23 elements is
the full M shell of Cu and Zn: $2\cdot3.2\cdot\sin10^\circ=1.11$ (L shell, $n=8$: $1.61$; M shell of Fe, $n=14$: $1.42$). (c)~follows from
Proposition~\ref{prop:onring}. \hfill$\square$

\paragraph{Time integration.} Each \code{OrbitNode} adds $s\,\omega_k\,\Delta t$ to its angle every frame, with $\Delta t$ measured by
\code{glfwGetTime}. For a constant angular speed this explicit update is exact (the increments sum to $s\,\omega_k t$), so the motion does not
depend on the frame rate. Taking the angle modulo $360^\circ$ keeps it in $[0,360)$, where a 32-bit float has a resolution of about
$3\times10^{-5}$ degrees; without the modulo the angle would reach $3.2\times10^5$ degrees after one hour, with a resolution of only $0.03^\circ$.
Moving the \emph{Speed} slider changes $\omega$ of all orbit nodes in place, so the electrons keep their phases. The rotation axis of an
orbit node is set when it is created, so an atom built while the animation is paused is drawn correctly too.

\paragraph{Apparent shape of the rings.} At these distances the projection is close to orthographic, so ring $k$ appears as an ellipse whose
axis ratio is the cosine of the angle between its normal and the viewing direction, $b/a=|\mathbf n_k\cdot\hat{\mathbf v}|$. In the default view
$\hat{\mathbf v}=-(0,\tfrac12,\tfrac{\sqrt3}{2})$, so $b/a=\bigl|\tfrac12\sin\tau_k-\tfrac{\sqrt3}{2}\cos\tau_k\bigr|=|\cos(\tau_k+30^\circ)|$:
$0.87$, $0.57$, $0.34$ and $0.71$ for K, L, M and N (Table~\ref{tab:shells}). The four rings appear as clearly different ellipses, none of
them edge-on (which would hide the electrons of a full shell behind each other), and this gives the atom its three-dimensional look even in a
still image. (The tilt of the M shell was lowered from $55^\circ$ to $40^\circ$ for this reason: $|\cos85^\circ|=0.09$.)

\subsubsection{Orbital rings: torus geometry}

Ring $k$ is the torus with major radius $R=r_k$ and tube radius $\rho$,
\begin{align*}
  \mathbf p(\vartheta,\phi)&=\bigl((R+\rho\cos\phi)\cos\vartheta,\ (R+\rho\cos\phi)\sin\vartheta,\ \rho\sin\phi\bigr),\\
  \mathbf n(\vartheta,\phi)&=(\cos\phi\cos\vartheta,\ \cos\phi\sin\vartheta,\ \sin\phi)=\frac{\mathbf p-R(\cos\vartheta,\sin\vartheta,0)}{\rho},
\end{align*}
sampled at $\vartheta_i=2\pi i/M$, $\phi_j=2\pi j/m$ ($i=0..M$, $j=0..m$, vertex index $i(m+1)+j$). The quad between $a=(i,j)$ and $b=(i{+}1,j)$
is split into $(a,b,a{+}1)$ and $(b,b{+}1,a{+}1)$. Since
$\partial_\vartheta\mathbf p\times\partial_\phi\mathbf p=\rho\,(R+\rho\cos\phi)\,\mathbf n$ with $R+\rho\cos\phi>0$, these triangles are
counter-clockwise when seen from outside, as required by back-face culling. $V=(M+1)(m+1)$, $I=6Mm$; with $M=128$, $m=8$: $V=1161$, $I=6144$.

\begin{lemma}
A uniform scaling by $\sigma$ maps the torus $(R,\rho)$ to the torus $(\sigma R,\sigma\rho)$.
\end{lemma}
\noindent This is immediate from the parametrisation, and it is the reason for having one torus per shell. Scaling a single unit torus to
the radius of each shell, as the previous version did with $\rho=0.025$, gives tubes of radius $0.025\,r_k=0.030,\ 0.053,\ 0.080,\ 0.1125$:
the N ring was thicker than an electron ($\rho_e=0.1$), whose sphere, centred on the centre circle, was then entirely inside the tube and
invisible (K, Ca, Fe, Cu, Zn), and the M electrons barely showed. Now seven tori with $R=r_k$ and the same $\rho=0.03<\rho_e$ are built once at
start-up, and the ring nodes are not scaled (the tests check $\det A=1$ for every ring).

\paragraph{Polygonal error.} The $M$-gon deviates from the true circle by at most the sagitta
$\delta=r\bigl(1-\cos(\pi/M)\bigr)\approx\pi^2 r/(2M^2)$: $3.6\times10^{-4}$ for the K ring and $1.4\times10^{-3}$ for the N ring, much smaller
than $\rho$, so an electron (which moves on the exact circle) always appears centred in its ring.

\subsubsection{Normalisation: centre of mass and similarity scaling}\label{sec:norm}

Molecules have very different sizes (NaCl is $2.4$~{\AA} long, N$_2$ $1.1$~{\AA}), so \code{MoleculeScene::build} maps every molecule
into the same sphere of radius $R_{\text{fit}}=2.2$ world units. With the standard atomic weights $m_i$ and covalent radii $r_i$:
\begin{equation}
  \mathbf c=\frac{\sum_i m_i\mathbf p_i}{\sum_i m_i},\qquad
  s=\frac{R_{\text{fit}}}{\max_i\bigl(\|\mathbf p_i-\mathbf c\|+\kappa r_i\bigr)},\qquad
  \mathbf x_i^0=s\,(\mathbf p_i-\mathbf c),\qquad \rho_i=s\,\kappa\,r_i,
  \label{eq:norm}
\end{equation}
with $\kappa=\tfrac12$; every bond radius is multiplied by $s$ as well.

\begin{proposition}\label{prop:similar}
The map $\Phi(\mathbf p)=s(\mathbf p-\mathbf c)$ is a similarity: $\|\Phi(\mathbf p)-\Phi(\mathbf q)\|=s\|\mathbf p-\mathbf q\|$ and all angles are preserved.
Since the radii are scaled by the same $s$, the rendered model is an exact scaled copy of the model in {\AA}ngstr\"om, its centre of mass is the
origin, and $\max_i(\|\mathbf x_i^0\|+\rho_i)=R_{\text{fit}}$: the farthest ball touches the fit sphere, which the camera framing keeps in view.
\end{proposition}
\noindent\textit{Proof.} $\Phi(\mathbf p)-\Phi(\mathbf q)=s(\mathbf p-\mathbf q)$, a positive multiple, which preserves ratios of lengths and angles;
$\sum_i m_i\mathbf x_i^0=s\bigl(\sum_i m_i\mathbf p_i-\mathbf c\sum_i m_i\bigr)=\mathbf 0$; the last identity is the definition of $s$. \hfill$\square$

Centring on the centre of mass (rather than on an arbitrary atom) is what a free molecule does: it rotates and vibrates about its centre of mass
(Section~\ref{sec:anim2}). For water the centre of mass is $(0,0.0656,0)$~{\AA}, almost on the oxygen ($m_{\text O}/m_{\text H}\approx16$), and
$s=2.049$: oxygen ball $0.748$, hydrogen ball $0.318$, O--H distance $1.961$ world units. The scale factors of the eight molecules are
$2.05$ (H$_2$O), $1.44$ (CO$_2$), $1.92$ (NH$_3$), $1.77$ (CH$_4$), $2.27$ (O$_2$), $2.38$ (N$_2$), $1.58$ (HCl) and $1.00$ (NaCl).

\paragraph{Why $\kappa=\tfrac12$.} Covalent radii are approximately additive, $d_{ij}\approx r_i+r_j$. Balls of radius $\kappa r$ then cover
$\kappa(r_i+r_j)\approx\kappa\,d_{ij}$ of every bond, and the visible part of each stick is about $(1-\kappa)\,d_{ij}=d_{ij}/2$: the balls never
touch (as they would in a space-filling model, $\kappa\ge1$) and the sticks do not dominate. The previous version scaled the positions but not
the radii, so the ball / stick proportions changed from one molecule to the other.

\subsubsection{Bond cylinders}\label{sec:bondcyl}

\paragraph{Mesh.} The shared cylinder has radius $\tfrac12$, height $1$ and axis $Y$. With $N=32$ segments and $a_i=2\pi i/N$ it has a side
ring of $2(N+1)$ vertices (bottom $b_i$ at index $2i$, top $t_i$ at $2i+1$, normal $(\cos a_i,0,\sin a_i)$), two cap centres and $2(N+1)$ cap-rim
vertices with normals $\pm\hat{\mathbf y}$: $V=4N+6=134$, $T=4N=128$, $I=12N=384$. The side quads are split into $(b_i,t_i,b_{i+1})$ and
$(t_i,t_{i+1},b_{i+1})$, for which
\[
  (\mathbf t_i-\mathbf b_i)\times(\mathbf b_{i+1}-\mathbf b_i)=(0,h,0)\times(\Delta x,0,\Delta z)=h\,(\Delta z,0,-\Delta x)
  \approx h\,r\,\Delta a\,(\cos a_i,0,\sin a_i),
\]
an outward vector: the triangles are counter-clockwise from outside (the caps likewise). The previous version used $(b_i,b_{i+1},t_i)$,
whose normal points inwards; with back-face culling the near half of every bond was discarded and the far half was drawn with normals pointing
away from the viewer, so the bonds were dull and had no highlight.

\paragraph{Placement.} For a strand from $\mathbf a$ to $\mathbf b$ let $\ell=\|\mathbf b-\mathbf a\|$, $\hat{\mathbf d}=(\mathbf b-\mathbf a)/\ell$,
$\mathbf m=(\mathbf a+\mathbf b)/2$ and
\begin{equation}
  M_{\text{bond}}=T(\mathbf m)\,R(\hat{\mathbf a},\theta)\,S(2\rho_b,\ \ell,\ 2\rho_b),\qquad
  \hat{\mathbf a}=\frac{\hat{\mathbf y}\times\hat{\mathbf d}}{\|\hat{\mathbf y}\times\hat{\mathbf d}\|},\qquad
  \theta=\operatorname{atan2}\bigl(\|\hat{\mathbf y}\times\hat{\mathbf d}\|,\ \hat{\mathbf y}\cdot\hat{\mathbf d}\bigr).
  \label{eq:bond}
\end{equation}

\begin{proposition}\label{prop:bond}
$M_{\text{bond}}(0,-\tfrac12,0)=\mathbf a$, $M_{\text{bond}}(0,\tfrac12,0)=\mathbf b$, and the transformed cylinder has radius $\rho_b$.
\end{proposition}
\noindent\textit{Proof.} $S(0,\pm\tfrac12,0)=(0,\pm\tfrac\ell2,0)$. Write $\hat{\mathbf d}=\cos\theta\,\hat{\mathbf y}+\sin\theta\,\hat{\mathbf w}$ with
$\hat{\mathbf w}\perp\hat{\mathbf y}$ a unit vector and $\theta\in[0,\pi]$; this is possible and consistent with~\eqref{eq:bond} because
$\hat{\mathbf y}\cdot\hat{\mathbf d}=\cos\theta$ and $\|\hat{\mathbf y}\times\hat{\mathbf d}\|=\sin\theta$. Then
$\hat{\mathbf y}\times\hat{\mathbf d}=\sin\theta\,(\hat{\mathbf y}\times\hat{\mathbf w})$, so $\hat{\mathbf a}=\hat{\mathbf y}\times\hat{\mathbf w}$, which is
perpendicular to $\hat{\mathbf y}$. Rodrigues' formula~\eqref{eq:rodrigues} with $\hat{\mathbf a}\cdot\hat{\mathbf y}=0$ and
$\hat{\mathbf a}\times\hat{\mathbf y}=(\hat{\mathbf y}\times\hat{\mathbf w})\times\hat{\mathbf y}=\hat{\mathbf w}(\hat{\mathbf y}\cdot\hat{\mathbf y})-\hat{\mathbf y}(\hat{\mathbf w}\cdot\hat{\mathbf y})=\hat{\mathbf w}$
gives $R\hat{\mathbf y}=\cos\theta\,\hat{\mathbf y}+\sin\theta\,\hat{\mathbf w}=\hat{\mathbf d}$. Hence
$M_{\text{bond}}(0,\pm\tfrac12,0)=\mathbf m\pm\tfrac\ell2\hat{\mathbf d}$, which are $\mathbf b$ and $\mathbf a$. The scale maps the circle of radius
$\tfrac12$ in the $XZ$ plane to radius $\rho_b$, and $R$ and $T$ preserve distances. \hfill$\square$

When $\hat{\mathbf y}\times\hat{\mathbf d}=\mathbf 0$ the axis is undefined: $\hat{\mathbf d}=\hat{\mathbf y}$ needs no rotation and
$\hat{\mathbf d}=-\hat{\mathbf y}$ needs a half turn about any axis perpendicular to $\hat{\mathbf y}$ (the code uses $\hat{\mathbf x}$).
$\operatorname{atan2}$ is preferred to $\arccos(\hat{\mathbf y}\cdot\hat{\mathbf d})$ because $\arccos'(x)=-1/\sqrt{1-x^2}$ diverges at $x=\pm1$:
near-vertical bonds would turn a rounding error $\varepsilon$ of the dot product into an angle error of order $\sqrt{2\varepsilon}$, whereas
$\operatorname{atan2}$ uses both the sine and the cosine and is well-conditioned for every direction.

\paragraph{Remark: the previous implementation.} The previous version built $R$ with \code{glm::rotate} and then recovered the axis--angle pair from
the matrix, $\theta=\arccos\frac{\operatorname{tr}R-1}{2}$ and $\hat{\mathbf a}=\frac{1}{2\sin\theta}(R_{32}-R_{23},\,R_{13}-R_{31},\,R_{21}-R_{12})$,
which is correct because $R-R^{T}=2\sin\theta\,[\hat{\mathbf a}]_\times$ by~\eqref{eq:rodrigues}. But GLM stores matrices column-major
(\code{m[col][row]}) and the entries were read as \code{m[row][col]}, which yields $-\hat{\mathbf a}$, i.e.\ the rotation $R^{T}=R^{-1}$. Since
$R^{T}\hat{\mathbf y}$ is the mirror image $(-d_x,d_y,-d_z)$ of $\hat{\mathbf d}$, the bonds of H$_2$O, NH$_3$ and CH$_4$ crossed the molecule instead
of joining the atoms (bonds along the $X$ axis happened to look right, $(\mp1,0,0)$ and $(\pm1,0,0)$ being the same line). The current code stores
$(\hat{\mathbf a},\theta)$ of~\eqref{eq:bond} directly, and Proposition~\ref{prop:bond} is checked for 300 random directions and all degenerate ones.

\subsubsection{Multiple bonds}

The strands of a double or triple bond are parallel copies of the bond shifted along
\[
  \hat{\mathbf u}=\frac{\hat{\mathbf d}\times\hat{\mathbf z}}{\|\hat{\mathbf d}\times\hat{\mathbf z}\|}
  \qquad\Bigl(\text{or }\frac{\hat{\mathbf d}\times\hat{\mathbf x}}{\|\hat{\mathbf d}\times\hat{\mathbf x}\|}\text{ if }\|\hat{\mathbf d}\times\hat{\mathbf z}\|<0.1\Bigr),
\]
a unit vector perpendicular to the bond and to $Z$: in the default view (camera on $+Z$) the strands lie side by side on the screen, as in a
structural formula, and for the planar molecules of the $XY$ plane they lie in the molecular plane. A double bond has two strands at
$\pm\delta_2\hat{\mathbf u}$, a triple bond three coplanar strands at $0,\pm\delta_3\hat{\mathbf u}$, all of radius $\rho_m$ (in {\AA}, before scaling):

\subsubsection{Configuring atom types and positions}\label{sec:editor}

Selecting a molecule copies its \code{MoleculeSpec} into a working copy which the editor of the control panel modifies:
\begin{itemize}
  \item every atom has an element selector (the 23 elements) and a position field $(x,y,z)$ in {\AA} that can be dragged or typed, and a
        button to remove it (its bonds are removed and the other bonds renumbered); \emph{Add atom} appends a hydrogen atom $1$~{\AA} beyond the
        atom with the largest $x$;
  \item every bond has an order slider (1--3) and a remove button; \emph{Add bond} joins two atom indices (validated: in range, distinct, not already bonded);
  \item \emph{Auto bonds} replaces the bond list by the result of the detection below; \emph{Reset} restores the preset.
\end{itemize}
Every change marks the scene dirty and it is rebuilt in the next frame ($O(n+B)$ nodes), so the centre of mass, the scale~\eqref{eq:norm} and the
bond cylinders are recomputed; the formula shown becomes the Hill formula of the current atoms (C and H first, then alphabetical) followed by
``(edited)'', and the experimental wavenumber of the preset is discarded.

\paragraph{Automatic bond detection.} Atoms $i<j$ are bonded if
\[
  \|\mathbf p_i-\mathbf p_j\|\le\tau\,(r_i+r_j),\qquad \tau=1.2,
\]
the additivity of covalent radii with a 20\,\% tolerance, tested for all $\binom n2$ pairs. For water, O--H: $0.957\le1.2(0.73+0.31)=1.248$ (bonded)
while H$\cdots$H: $1.514>1.2\cdot0.62=0.744$ (not bonded); for NaCl, $2.361\le3.036$. On the eight presets the detection finds exactly their bonds
(tested). The bond order cannot be inferred from distances alone and is set by the user.

\paragraph{Geometry read-out.} The panel lists, for the current atoms, every bond length $\ell_{ij}=\|\mathbf p_i-\mathbf p_j\|$ and every bond angle
at an atom $j$ shared by two bonds $(i,j)$ and $(j,k)$,
\[
  \vartheta_{ijk}=\arccos\frac{(\mathbf p_i-\mathbf p_j)\cdot(\mathbf p_k-\mathbf p_j)}{\|\mathbf p_i-\mathbf p_j\|\,\|\mathbf p_k-\mathbf p_j\|},
\]
with the argument clamped to $[-1,1]$ against rounding. For example, turning water into hydrogen sulfide (O$\to$S and the H atoms moved to
$(\pm0.962,\,0.927,\,0)$) shows S--H $=1.336$~{\AA} and H--S--H $=92.1^\circ$, the experimental values (Figure~\ref{fig:p2edit}).

\subsubsection{Molecular vibration: physical background}

Near the equilibrium geometry $\mathbf x^0\in\mathbb R^{3n}$ the potential energy is approximately quadratic,
$U(\mathbf x^0+\boldsymbol\xi)\approx U_0+\tfrac12\boldsymbol\xi^{T}H\boldsymbol\xi$ ($\nabla U=\mathbf 0$ at equilibrium, $H$ the Hessian),
and Newton's law gives $\mathsf M\ddot{\boldsymbol\xi}=-H\boldsymbol\xi$ with $\mathsf M=\operatorname{diag}(m_1I_3,\dots,m_nI_3)$. Solutions
$\boldsymbol\xi=\mathbf q\cos(\omega t+\varphi)$ exist when
\[
  H\mathbf q=\omega^2\mathsf M\mathbf q
  \quad\Longleftrightarrow\quad
  \bigl(\mathsf M^{-1/2}H\mathsf M^{-1/2}\bigr)\tilde{\mathbf q}=\omega^2\tilde{\mathbf q},\qquad \tilde{\mathbf q}=\mathsf M^{1/2}\mathbf q,
\]
a symmetric eigenvalue problem whose eigenvectors are the \emph{normal modes}~\cite{wilson,molvib}. Three translations and three rotations (two for a
linear molecule) cost no energy and have $\omega=0$, leaving $3n-6$ vibrations ($3n-5$ if linear): 3 for H$_2$O, 6 for NH$_3$, 9 for CH$_4$, 4 for CO$_2$
and 1 for a diatomic molecule. For a diatomic molecule the problem reduces to one oscillator in the bond length with the reduced mass
$\mu=m_1m_2/(m_1+m_2)$:
\[
  \mu\,\ddot x=-k\,x,\qquad \omega=\sqrt{k/\mu},\qquad \tilde\nu=\frac{\omega}{2\pi c}.
\]
For HCl, $\mu=0.980$~u and $\tilde\nu=2886$~cm$^{-1}$ give the force constant $k=\mu(2\pi c\tilde\nu)^2\approx481$~N/m. A mode absorbs infrared light
only if it changes the dipole moment ($\partial\boldsymbol\mu/\partial q\ne\mathbf 0$)~\cite{ir}: the stretch of the homonuclear O$_2$ and N$_2$ and the
symmetric stretches of CO$_2$ and CH$_4$ are IR-inactive and observed in Raman spectra instead (Table~\ref{tab:molecules}).

\subsubsection{Implemented vibration: symmetric stretching}

Every atom is wrapped in a \code{VibrationNode} that moves it on the line through the centre of mass, all atoms in phase:
\begin{equation}
  \mathbf x_i(t)=\lambda(t)\,\mathbf x_i^0,\qquad \lambda(t)=1+A\sin(2\pi f t),
  \label{eq:breathing}
\end{equation}
with $\mathbf x_i^0$ from~\eqref{eq:norm} (relative to the centre of mass), the relative amplitude $A$ (default $0.08$, slider $0$--$0.25$) and the
displayed frequency $f$.

\begin{proposition}\label{prop:vib}
For every molecule, the motion~\eqref{eq:breathing} (a)~keeps the centre of mass at the origin, (b)~has zero total linear momentum,
(c)~has zero total angular momentum, and (d)~multiplies every interatomic distance by $\lambda(t)$ while keeping every bond direction and every
bond angle constant.
\end{proposition}
\noindent\textit{Proof.} (a)~$\sum_i m_i\mathbf x_i=\lambda\sum_i m_i\mathbf x_i^0=\mathbf 0$ by Proposition~\ref{prop:similar}.
(b)~$\mathbf P=\sum_i m_i\dot{\mathbf x}_i=\dot\lambda\sum_i m_i\mathbf x_i^0=\mathbf 0$.
(c)~$\mathbf L=\sum_i m_i\,\mathbf x_i\times\dot{\mathbf x}_i=\lambda\dot\lambda\sum_i m_i\,\mathbf x_i^0\times\mathbf x_i^0=\mathbf 0$.
(d)~$\mathbf x_i-\mathbf x_j=\lambda(\mathbf x_i^0-\mathbf x_j^0)$ with $\lambda>0$. \hfill$\square$

So the motion is purely internal --- no drift and no spurious rotation, properties shared by every normal mode. It is exactly the vibration of a
diatomic molecule (the displacements are along the axis, with $\|\Delta\mathbf x_1\|/\|\Delta\mathbf x_2\|=m_2/m_1$: in HCl the hydrogen atom moves
$35.2$ times more than the chlorine atom), and exactly the symmetric stretch $\nu_1$ of CO$_2$ (carbon at rest, the two oxygen atoms moving in
opposite directions) and of CH$_4$ (carbon at rest, the four H atoms moving radially): these modes are the only ones of their symmetry species
($\Sigma_g^+$, $A_1$), so symmetry alone fixes their pattern. Water and ammonia have two totally symmetric modes (stretch and bend), and their true
$\nu_1$ contains a little bending; \eqref{eq:breathing} is its stretching part. Asymmetric and bending modes would require the eigen-decomposition
above and are not implemented.

\paragraph{Frequency.} The displayed frequency is proportional to the experimental wavenumber, $f=10^{-3}\tilde\nu_1$~Hz (times the \emph{Vib.\ speed}
multiplier): $3.66$~Hz for water, $2.89$~Hz for HCl, $1.33$~Hz for CO$_2$, $0.37$~Hz for NaCl. Relative frequencies are therefore physical (light
atoms and stiff bonds vibrate faster, $\omega=\sqrt{k/\mu}$); the real motion, at $c\tilde\nu$, is slowed down by $c\tilde\nu/f=3.0\times10^{13}$. An
edited molecule, whose wavenumber is unknown, vibrates at 2~Hz.

\paragraph{Bonds follow the atoms.} After the atoms have moved, every strand is placed again with~\eqref{eq:bond} between the current
$\mathbf x_a$ and $\mathbf x_b$ (plus its sideways offset), so the sticks stretch and shrink with the vibration. The previous version moved each atom
independently along $x$, $y$ or $z$ at different frequencies and left the bonds in place: the centre of mass moved, the molecule rotated and
the atoms drifted away from their bonds.

\subsubsection{Molecular rotation}

The root \code{MolRotNode} applies $R_y(\omega_r t)$ with $\omega_r=30^\circ$/s about the vertical axis through the centre of mass (the origin after
normalisation), the axis about which a free molecule rotates. Atom $i$ is drawn with
\[
  M_{\text{world},i}(t)=R_y(\omega_r t)\;T\bigl(\lambda(t)\,\mathbf x_i^0\bigr)\;S(\rho_i),
\]
and since $R_y(\lambda\mathbf x)=\lambda R_y\mathbf x$ (a rotation is linear), rotation and vibration commute: either can be switched on or off at
any time. Bond strands are children of the same root, so they rotate with the atoms. Editing a molecule keeps its current rotation angle.

\paragraph{Shaders.} The vertex shader computes \code{FragPos = vec3(model * vec4(aPos, 1))}, \code{Normal = normalMatrix * aNormal} and

\begin{lstlisting}[language=GLSL,caption={Fragment shader core (phong.frag).}]
vec3 ambient  = light.ambient * material.ambient;

vec3 norm     = normalize(Normal);
vec3 lightDir = normalize(light.position - FragPos);
float diff    = max(dot(norm, lightDir), 0.0);
vec3 diffuse  = light.diffuse * (diff * material.diffuse);

vec3 viewDir    = normalize(viewPos - FragPos);
vec3 reflectDir = reflect(-lightDir, norm);
float spec      = diff > 0.0 ? pow(max(dot(viewDir, reflectDir), 0.0), material.shininess) : 0.0;
vec3 specular   = light.specular * (spec * material.specular);

FragColor = vec4(ambient + diffuse + specular, 1.0);
\end{lstlisting}

\subsection{Testing and Verification}\label{sec:test2}

\code{make test} (in \code{part2\_molecules}, or at the top level for both parts) builds \code{tests/test\_part2.cpp}, which needs no window: the scenes
are built with dummy meshes and only their transforms are inspected. It checks:
\begin{itemize}
  \item \textbf{meshes}: $V$ and $I$ equal the closed forms above, all indices are valid, all normals have unit length, every non-degenerate triangle is
        counter-clockwise seen from outside ($(\mathbf b-\mathbf a)\times(\mathbf c-\mathbf a)\cdot(\mathbf n_a+\mathbf n_b+\mathbf n_c)>0$), and every torus vertex is
        at distance $\rho$ from the centre circle;
  \item \textbf{Bohr atoms} (all 23 elements): $\sum_k n_k=Z$ and $n_k\le2k^2$; at $t=0$, after several time steps, and for an atom built while paused,
        every electron satisfies $\|\mathbf c\|=r_k$ and $\mathbf c\cdot\mathbf n_k=0$ (Proposition~\ref{prop:onring}), every ring is rigid and centred on its
        orbit, the distances of Proposition~\ref{prop:nooverlap} hold, and one update turns each orbit by exactly $s\,\omega_k\,\Delta t$;
  \item \textbf{molecules} (all 8): bond lengths and angles equal the reference values of Table~\ref{tab:molecules} ($\pm0.002$~{\AA}, $\pm0.1^\circ$);
        bond detection finds exactly the preset bonds; positions are the similarity image~\eqref{eq:norm} and the fit radius is reached
        (Proposition~\ref{prop:similar}); every strand joins its two atoms, with the right radius, a perpendicular offset and both ends inside the balls
        (Proposition~\ref{prop:bond}); parallel strands do not touch; the normal matrix keeps normals perpendicular to the surface
        (Proposition~\ref{prop:normal}); during the vibration the centre of mass stays at the origin and all positions are $\lambda(t)\mathbf x_i^0$
        (Proposition~\ref{prop:vib}); with the rotation everything stays attached;
  \item \textbf{bond placement} for 300 random segments and the degenerate directions $\pm\hat{\mathbf y}$.
\end{itemize}
All 13\,607 checks pass. As a control, re-introducing either defect of the previous version (clockwise cylinder triangles, or the transposed axis
of the bond rotation) makes the corresponding checks fail.

\subsection{Limitations}\label{sec:lim2}

\begin{itemize}
  \item Bohr's model is semi-classical: electrons do not move on circles but occupy orbitals (probability clouds), and the model is quantitatively
        valid only for one-electron atoms. The rings, their tilts and the compressed radii and speeds are a visual convention
        (Section~\ref{sec:bohrvis}), not to scale. Only 23 elements are in the table (up to four shells).
  \item Molecules come from 8 presets that the editor can modify; there is no import of molecular files (\code{.xyz}, \code{.mol}) and no saving of
        edited molecules. Bond orders are not inferred. The molecule is re-centred and re-scaled after every edit, so it may appear to change size while
        an atom is dragged.
  \item Geometries are fixed experimental values; there is no force field or geometry optimisation. The vibration is the symmetric stretch only (exact
        for diatomics, CO$_2$ and CH$_4$, approximate for H$_2$O and NH$_3$); bending and asymmetric modes would need the normal-mode analysis of
        Section~\ref{sec:anim2}.
  \item Atom labels are not drawn in the 3D view; the CPK legend and the geometry read-out of the panel identify the atoms.
\end{itemize}


% ------------------------------------------------------------------ 2.8
\subsection{Limitations}\label{sec:lim2}

\begin{itemize}
  \item Only 23 elements are included in the look-up table; elements beyond Zn are not available. The molecule list is fixed at compile time (8 molecules); the user cannot define new molecules at runtime.
  \item Bohr's model is a simplification: in reality electrons do not orbit in fixed circular paths but occupy probability clouds (orbitals). The tilted-ring visualization is a pedagogical convention, not a physical representation.
  \item Bond lengths and angles are hard-coded from approximate experimental data; no force-field relaxation or geometry optimization is performed.
  \item The ball-and-stick model uses the molecule mode that is currently commented out in the GUI radio buttons (the code is complete but the UI toggle to switch to it is disabled in the delivered version). Users would need to uncomment the radio button in \code{main.cpp} (lines~187--191) to enable it.
  \item There is no screenshot function in Part~2 (unlike Part~1 which uses \code{stb\_image\_write}). Screenshots must be taken with an external tool.
  \item The vibration animation is a simplified sinusoidal oscillation along a single axis per atom, not a physically accurate normal-mode analysis.
  \item Atom labels (element symbols displayed next to each sphere) are not rendered; the CPK color legend in the GUI is the only way to identify atoms.
\end{itemize}


% ------------------------------------------------------------------ conclusion
\section{Conclusion}\label{sec:conclusion}

Both applications are built on the same OpenGL~3.3 core-profile foundation and on the shared code in \code{common/} (shader loading, orbit camera, ImGui, GLM), so
the two parts are independent programs that reuse the same graphics infrastructure.

\subsection{Part 1}
Part~1 draws all required 2D and 3D shapes, a user-defined surface and imported \code{.obj} / \code{.ply} models; supports the five render modes
(flat, Gouraud, Phong, texture, wireframe); lets the user translate, rotate and scale every object and navigate with mouse and keyboard; and is organised in small modules of which the geometry,
parsing and loading parts are independent from OpenGL.

\subsection{Part 2}
Part 2 visualizes atoms with Bohr's model (23 elements, one tilted ring per shell, electrons that provably stay on their rings and never overlap)
and molecules with the ball-and-stick model (8 molecules with experimental geometry, CPK colors, balls proportional to the covalent radii, bonds of
one to three strands placed by an exact axis--angle construction). It lets the user configure the element of the atom and the type and position of
every atom of a molecule, with automatic bond detection and a geometry read-out. It animates the electron motion, a symmetric stretching vibration
that conserves the centre of mass and the momenta, and a rotation about the centre of mass, and it frames the camera automatically and saves
screenshots. The scene graph composes all transformations, the meshes are shared, every node has its own material under per-fragment Phong
lighting.
